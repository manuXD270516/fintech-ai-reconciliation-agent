# Modelos C4

Diagramas Mermaid con semántica de C4: personas, sistemas, contenedores, responsabilidad y protocolo. Describen la arquitectura objetivo M0–M10; no el estado implementado. Un contenedor C4 es una unidad ejecutable o de almacenamiento, no necesariamente un Docker container.

## C4 context

```mermaid
flowchart LR
    ops["Persona: Analista de operaciones"]
    approver["Persona: Supervisor aprobador"]
    audit["Persona: Auditor"]
    curator["Persona: Curador de conocimiento"]
    internal["Sistema externo: Plataforma / ledger sintético"]
    provider["Sistema externo: Procesadores y APIs sintéticas"]
    files["Sistema externo: Archivos de conciliación"]
    docs["Sistema externo: Docs, runbooks e incidentes sintéticos"]
    identity["Sistema externo: Proveedor de identidad"]
    llm["Sistema externo: Modelos de lenguaje y embeddings"]
    system["Sistema: Fintech AI Reconciliation Agent\nConciliación, investigación, evidencia y revisión humana"]
    ops -->|"HTTPS: consultar e investigar"| system
    approver -->|"HTTPS: aprobar o rechazar"| system
    audit -->|"HTTPS: consultar trazabilidad"| system
    curator -->|"HTTPS: gestionar versiones de knowledge"| system
    internal -->|"HTTPS / eventos: observaciones"| system
    provider -->|"HTTPS / eventos: pagos y estados"| system
    files -->|"Upload: CSV sintético"| system
    docs -->|"Ingestión autorizada"| system
    system -->|"Validación de identidad / scopes"| identity
    system -->|"HTTPS: contexto minimizado"| llm
```

No hay flecha de ejecución financiera hacia el ledger/procesador: todos los conectores operativos del MVP son de lectura/recepción. Proveedor de identidad externo es requerido para demo pública; en local se prevé identidad de desarrollo explícita y restringida a loopback.

## C4 container model

```mermaid
flowchart TB
    people["Personas: Analista / Supervisor / Auditor / Curador"]
    sources["Fuentes externas sintéticas\nCSV, API, eventos, documentación"]
    idp["Proveedor de identidad"]
    models["LLM / Embeddings\nAPI externa o adaptador local"]
    subgraph boundary["Sistema: fintech-ai-reconciliation-agent"]
        web["Web App — React / TypeScript\nRevisión de casos y evidencia"]
        api["API — FastAPI\nAuth, comandos, consultas, aprobación humana"]
        work["Domain Worker — Python\nIngestión, normalización, reglas, knowledge jobs, outbox relay"]
        bus["Event Bus — NATS JetStream\nStreams persistidos y consumidores durables"]
        agent["Investigation Worker — Python\nOrquestación, evidence checks y reviewer"]
        mcp["fintech-mcp-server — Python\nSeis tools de sólo lectura con autorización"]
        db[("PostgreSQL + pgvector\nDatos por contexto, FTS, vectores, audit, outbox/inbox")]
        artifacts[("Volumen de artefactos sintéticos\nArchivos y documentos versionados")]
        telemetry["OpenTelemetry Collector / Backend\nLogs, métricas y trazas; M9"]
    end
    people -->|"HTTPS"| web
    web -->|"HTTPS / JSON"| api
    sources -->|"HTTPS ingestion"| api
    sources -->|"Eventos de adaptadores autorizados"| bus
    api -->|"OIDC / verificación de tokens"| idp
    api -->|"SQL: consultas y transacciones"| db
    api -->|"IO: persistir inputs"| artifacts
    work <-->|"SQL: estado, jobs, outbox/inbox"| db
    work <-->|"Publish / consume / ack"| bus
    work -->|"IO: leer fuente versionada"| artifacts
    work -->|"Embeddings"| models
    agent <-->|"Consume / publish mediante outbox"| bus
    agent -->|"SQL: sólo investigación y outbox/inbox"| db
    agent -->|"MCP Streamable HTTP interno"| mcp
    mcp -->|"SQL / fachadas read-only + ACL"| db
    agent -->|"HTTPS: generación estructurada"| models
    api -->|"OTLP"| telemetry
    work -->|"OTLP"| telemetry
    agent -->|"OTLP"| telemetry
    mcp -->|"OTLP"| telemetry
```

Los roles DB limitan cada proceso; el agente no tiene permisos sobre decisiones humanas ni registros transaccionales. El servidor MCP accede sólo a vistas/fachadas autorizadas de dominio y knowledge. Provider status usa snapshots sintéticos persistidos en el MVP. El bus no se expone a Internet. El worker publica eventos propios por outbox; las flechas al bus no habilitan dual writes sin atomicidad.

M0 prepara únicamente API, DB y bus y su validación técnica. El resto se incorpora según roadmap. El dashboard se despliega como estáticos; API y MCP usan autenticación diferenciada. El protocolo local MCP también admite stdio para desarrollo, manteniendo el mismo contrato de tools.
